Final round: four launch-blocking bugs found by actually using the app

Nobody had ever tapped Install and received a model. Doing that on a real
phone surfaced, in order:

1. POST_NOTIFICATIONS was declared but never requested. On Android 13+ it is
   a runtime grant, the foreground download service could not post its
   notification, and the system killed the job seconds in - with exponential
   backoff stretching retries to forty minutes. Every modern phone would have
   hit this. The activity now asks once up front, and the worker treats a
   missing notification as cosmetic rather than fatal.

2. WorkManager's SystemForegroundService is declared with no
   foregroundServiceType, and on Android 14+ the type passed at runtime must
   be a subset of the manifest's. It threw on the MAIN thread inside the
   service and took the whole process down - unreachable from any try/catch
   in a worker. The crash handler built earlier caught it and named the exact
   cause. Fixed with a manifest merge declaring dataSync.

3. The first successful download sat at 428 MB on disk while the UI said
   NOT INSTALLED. The worker records the install in SQLite, but nothing about
   a database row redraws a screen. The UI now observes the WorkInfo and
   refreshes on completion.

4. "Add to home screen" lived on a settings screen nothing links to since the
   drawer redesign - the app's headline feature was unreachable. It is now a
   PIN action in the drawer, one tap from the model it pins.

Also: shared libraries are now 16 KB page-aligned (NDK 28 plus explicit
max-page-size), which Android 15+ devices require and Play enforces; the
system warned about it in a compatibility dialog mid-test.

Verified on hardware, end to end: install tapped, consent shown, 409 MB
downloaded through the real pipeline, chat answered, icon pinned, cold tap
on the icon opened straight into that model's chat. The rebuilt release APK
is live on the site; the previously hosted one carried all four bugs.

tools/drive.sh drives the UI over adb with a focus guard that refuses to tap
unless the app is in front - added after a blind tap landed in the wrong app.
